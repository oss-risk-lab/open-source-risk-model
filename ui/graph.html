What This Graph Means ▼

Understanding the Graph

This visualization shows the supply chain relationships for a repository. Each node represents an entity (repository, release, maintainer, vulnerability, etc.), and edges show how they're connected.

Node Types

  • Repository — The analyzed project (center node)
  • Release — Published versions/tags
  • Maintainer — Key contributors
  • CVE — Known security vulnerabilities
  • Registry — Package distribution channels (PyPI, npm, etc.)
  • Risk Factor — Metrics driving the risk score

Provenance & Confidence

Provenance tells you where each data point came from:

  • github_api — Authoritative data from GitHub (confidence: 0.9-1.0)
  • github_advisory / osv — CVE data from security databases (confidence: 0.95)
  • heuristic — Detected from file analysis (confidence: 0.7-0.8)
  • score_model — Calculated risk metrics (confidence: varies)

Confidence scores (0.0-1.0) indicate data reliability. Lower confidence means more uncertainty.

How CVE Matching Works

CVEs are linked to releases using version range matching from vulnerability databases. This is heuristic-based and may have false positives/negatives. Check the match_confidence field for reliability.

Limitations

  • Registry detection is file-based (not API-verified)
  • CVE-to-version matching uses heuristics
  • Maintainer data reflects GitHub's contribution tracking
  • Cached data may be up to 1 hour old

Interpreting Risk

Risk factors show which metrics contribute most to the overall maintenance risk score. Higher contribution = bigger impact on risk. Click nodes to see detailed metadata and provenance.
